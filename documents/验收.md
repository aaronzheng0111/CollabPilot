# 验收

一次会话、同一活动走完。除特别说明外不要刷新重置。

## 启动

```bash
cd frontend && uv run --project ../backend --extra ui streamlit run app.py
```

浏览器打开 http://localhost:8501。假定 `backend/.env` 已有 `DEEPSEEK_API_KEY`。

示例需求（后文简称「示例 brief」）：

> 为一款面向中文用户的 AI 翻译工具，找 10 位使用这个翻译工具的创作者。优先选择最近持续发布相关内容的人，排除已经合作过的账号。整理候选名单，并为最合适的 3 位准备合作邀请草稿。发送前让我审核。

---

## T01 会话

- [ ] 左栏主表宽、右栏对话窄；对话在右侧高框内，底部有「发送」
- [ ] 框内输入「你好」并发送：助手回复流式出现；工具行在助手气泡内（旋转 +「正在调用 …」→ 绿「… 调用完成」），无独立工具行、无「空闲」胶囊
- [ ] 再发一句，历史仍可见上一轮；用户/助手气泡各有「删除」；删助手气泡会带走该轮工具行
- [ ] 错误或状态文案里看不到 API Key

## T02 目标

- [ ] 输入「帮我找达人」并发送：主表出现「需求未完成，表格暂无筛选结果」；助手至少 2 个编号追问，且含「推荐过滤」；对话中不得出现「换一种说法」标题或整段改写目标
- [ ] 解析目标时不再追问「为其中多少位准备邀请草稿」；在过滤后的表点该达人行的「生成草稿」即可（一次一位）
- [ ] 解析/澄清/待你确认的假设中不再出现「草稿发送前是否需要你审核」或 `needs_user_approval`；未写明时静默默认需审核，不阻塞 PARSED
- [ ] 粘贴示例 brief 并发送：左栏出现「合作目标」卡片（人数 10、触达可空/按勾选、需审核、排除已合作）；缺品牌/平台等标「假设」
- [ ] 右栏「待你决定」（对话框内、输入框上方）无待办时显示「目前没有需要你决定的事项」（若有确认假设，点批准后消失）
- [ ] 新建项目，或本会话再发「可以和已经联系过的人再次取得联系」：不得再出现要求确认「排除已合作」的待你决定项

## T03 搜索

（若 brief 后未自动搜，在对话里说「开始搜索」。）

- [ ] 运行中主表加载文案含 `search_creators`；完成后主表有多行创作者（替换原先「示例达人」）
- [ ] 行带 `[MOCK]`；同一人跨平台合并为一行
- [ ] 表上方可见本轮搜索参数（关键词 / 时间窗口等）

## T04 硬过滤

- [ ] 过滤完成后主表只剩保留行
- [ ] 展开「已排除」：可见已合作本品牌者，原因含合作品牌与日期，带 `[RULE]`
- [ ] 已排除者不再出现在主表

## T05 匹配判断

- [ ] 主表出现中文决策与 rank；「合适」按 rank 升序排在「待确认」「不合适」之前，带 `[LLM]`
- [ ] 「查看判断依据」选一位合适者：见理由、帖子原文、时效/持续性、`deepseek-chat`
- [ ] 依据面板为深色；无 `expected_decision_hint` 等测试字段

## T06–T08 主题不符 · 人数不足 · 受众未知（手测）

一次搜索同时验两案。示范：主题不符「翻译剪辑君」`creator_011`（品类 Beauty、内容主题护肤/口红/妆教/测评化妆品；同批「英语考试通」「AI绘画Mia」「留学申请Nina」「小语种备考Owen」亦为美妆，昵称可命中关键词但主题不符）；受众未知「Tina工具箱」「Uma译记」`creator_020`/`021`（另有 Vince跨境、Wendy留学译）；合适常见为 Amy学翻译、跨境效率Ben、职场翻译Cora、留学沟通Derek、术语库Eva、多产品测评Frank（`001`–`006`）。

**粘贴 brief：**

> 为一款面向中文用户的 AI 翻译工具，找 10 位正在使用这款翻译工具、最近持续发布相关内容的创作者。整理候选名单。

- [ ] 若右栏出现「待你决定」假设项，点**批准**；再发「开始搜索」（未自动搜时）

**回复短式（无大段 id 列表）：**

- [ ] 含「合格 n/10」（n 常约 6、必小于 10）、主题不符人数「未入名单」、受众未知人数「待确认未计入合格」，并写下一步（接受当前短名单，或点一位合适达人「生成草稿」）
- [ ] 主表 /「判断依据」：「翻译剪辑君」为「不合适」+「主题不符」，有帖子 quote，**不在**合适名单
- [ ] 「Tina工具箱」「Uma译记」为「待确认」+「受众未知」，**不是**「合适」；待确认列表与合适分开

**待你决定「是否接受」：**

- [ ] 文案「当前合格 n 位」与回复「合格 n/10」一致，且 n≠0（有合适时）；主题不符、受众未知**不计入**合格
- [ ] 左栏「进度」合格 n/10 与缺口一致；演示默认**不**自动再搜凑满 10，首轮不足即出「是否接受」；草稿区仍空 → 点**批准**继续

**若本轮碰巧合格满 10：**

- [ ] 不必另搜；回复仍单独列出受众未知；「Tina工具箱」等仍在待确认，**不在**那 10 位合适里

## T09 保存名单

- [ ] 主表勾选：合适者默认勾选，待确认可勾，不合适/锁定不可勾
- [ ] 点「保存到活动」→「待你决定」出现保存项 → 点**批准**：主表出现 saved 标记
- [ ] （可选）排除一位已保存者并批准后进「已排除」；同需求再跑时表上方可见跳过人数说明

## T13 沟通渠道

- [ ] 左栏「沟通渠道」：每平台一行，渠道来自资料且带 `[MOCK]`；未知同意状态显示「未知」
- [ ] 有可用渠道的行可「确认渠道」；无渠道行无确认按钮
- [ ] 确认进入「待你决定」，批准后主表有 channel；渠道区无发送类按钮

## T10 触达草稿

（过滤后的表对每位达人单独点「生成草稿」；不必先确认渠道。不要一次给所有勾选的人批量写草稿。）

- [ ] 主表每位可选达人有「生成草稿」：点一位立刻只落库该达人一封草稿并弹出窗口（创作者、渠道、引用、正文、状态「待审核」，带 `[LLM]`）；关闭后右栏仍有列表与「查看草稿」可再打开已写过的草稿
- [ ] 对话发「生成草稿」且未点名达人时：不写草稿，提示「请在表里点该达人的生成草稿」
- [ ] 弹窗与列表均有「草稿不会发送」，无发送按钮；左栏无草稿块
- [ ] 在「待你决定」逐封**批准**（退回为拒）后显示「已批准」

## T14 跟进

- [ ] 草稿批准后「待你决定」出现记录跟进；批准后左栏「跟进」有行：创作者、渠道、下一步、中文状态，带 `[LLM]`
- [ ] 再批准「记下」后状态变为「已记下」；文案含「记下不等于发送」/`[MOCK-SEND]`
- [ ] 跟进区无发送类按钮

## T11 工作台集成

（同一活动页扫一眼，不必重跑。）

- [ ] 左栏：主表 → 有数据的次级块（目标/进度/依据/待确认/已排除/渠道/跟进）；「待你决定」与草稿在右栏对话框内、输入框上方
- [ ] 奶油色底、衬线标题；珊瑚色主要出现在批准按钮
- [ ] 约 1440 与约 1024 宽时两栏完整可见，无整页横向滚动
- [ ] 刷新或侧栏切回本项目后，右栏对话历史仍在

## T12 来源标签

- [ ] 达人行 / 渠道 / 帖子相关展示带 `[MOCK]`
- [ ] 判断、再搜策略、草稿、跟进带 `[LLM]` 与 `deepseek-chat`
- [ ] 已合作排除、主题锁定、受众改判带 `[RULE]`；草稿标明不会发送
- [ ] 整页无顶部图例行（`[MOCK] 模拟数据` … `[MOCK-SEND] 不会发送`）；行内来源标签仍在
- [ ] 整页文案看不到 API Key
